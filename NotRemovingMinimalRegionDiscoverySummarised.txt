================================================================================
DISCOVERY SUMMARY: PRESERVING COMPOSITE REGIONS FOR EVENT EFFECTIVENESS
IN PETRI NET SYNTHESIS
================================================================================

1. THE BIG PICTURE: HOW REGION SYNTHESIS IS SUPPOSED TO WORK
--------------------------------------------------------------------------------
Think of a Transition System (TS) as a map of states (markings) and events 
(transitions). A Petri net place acts as a container of tokens controlling when 
an event can fire:
  - An event 'e' can fire only if all its input places have tokens.
  - When 'e' fires, it consumes tokens from input places and produces tokens 
    into output places.

In Region Theory:
  1. A Region (r) is a set of states where a place holds a token.
  2. The Excitation Region ER(e) is the set of all states from which event 'e' 
     can fire.
  3. A Preregion of 'e' is any region that covers ALL states in ER(e). In the 
     derived Petri net, every preregion becomes an input place to 'e'.

The Golden Rule of Petri Nets:
Every event that ever fires must have at least one input place (unless it is a 
source event). If an event has NO input places, standard Petri net semantics 
treat it as "always enabled" — meaning it can fire at any random time, completely 
unconstrained!


2. THE TRAP: WHY DID THE STANDARD ALGORITHM DROP NEEDED REGIONS?
--------------------------------------------------------------------------------
In Carmona et al. (IEEE TC 2010), the authors wanted the synthesized Petri net 
to be as compact as possible. To keep the net minimal, they defined Minimal 
Regions:
  - If region r_A has states {s1, s2} and region r_B has states {s1, s2, s3, s4}, 
    then r_A is strictly smaller than r_B.
  - Region r_B is labeled "non-minimal" (or composite) because it is a superset / 
    sum of smaller valid regions.
  - In Carmona's Algorithm 2, there is an unconditional pruning step:
        removeNonMinimal(candidates)
    which dictates: "If a valid region contains a smaller valid region inside it, 
    throw it away!"

This rule works for textbook examples where processes are strictly block-structured. 
However, in workflows with concurrency, background loops, or multi-phase activities, 
this rule creates a fatal blind spot.


3. THE CONCRETE TRAP: WHAT HAPPENED IN ITERATION 2?
--------------------------------------------------------------------------------
Consider the workflow tested in Iteration 2 with events 'a', 'b', and 'c':
  - Event 'a' fires at the start.
  - Event 'c' is a milestone step that splits the process into two sequential phases:
        Phase 1 (Before c): States {s1, s4, s6}
        Phase 2 (After c):  States {s2, s3, s5, s7, s8}
  - Meanwhile, event 'b' is an ongoing background task / loop that can occur 
    repeatedly in Phase 1 AND can continue to occur repeatedly in Phase 2!

Look at the regions found during Breadth-First Search (BFS):

        [ Phase 1: Before c ]                 [ Phase 2: After c ]
        States: {s1, s4, s6}                  States: {s2, s3, s5, s7, s8}
        
        Region r_1 covers this                Region r_0 covers this
                   \                                     /
                    \                                   /
                     v                                 v
                   [ Region r_3 covers BOTH: {s1, s2, ..., s8} ]

Notice the algebraic relationship:
    r_3 = r_1 + r_0

Because r_1 is a subset of r_3, and r_0 is a subset of r_3:
  1. The textbook algorithm invokes removeNonMinimal().
  2. It inspects r_3 and reasons: "r_3 contains r_1 and r_0, so r_3 is composite 
     and non-minimal. Delete r_3!"
  3. Consequently, only r_1 and r_0 survive into the region pool.


4. THE DISASTER: WHY EVENT 'b' WAS LEFT WITH NO INPUT PLACE
--------------------------------------------------------------------------------
The synthesis engine then executes Algorithm 1 to derive the Petri net:
To give event 'b' an input place, it searches for a region that covers ALL states 
where 'b' can fire:
    ER(b) = {s1, s4 (from Phase 1),   s2, s3 (from Phase 2)}

It evaluates the surviving regions:
  - Does r_1 cover ER(b)?
    NO! r_1 only covers Phase 1. It has 0 tokens in states s2 and s3.
  - Does r_0 cover ER(b)?
    NO! r_0 only covers Phase 2. It has 0 tokens in states s1 and s4.
  - Does r_3 cover ER(b)?
    YES! r_3 covers both Phase 1 and Phase 2!
    ... BUT r_3 WAS ALREADY DELETED BY removeNonMinimal()!

The result:
  - Neither r_1 nor r_0 can serve as an input place to 'b'.
  - The algorithm finds ZERO preregions for 'b'.
  - In iteration_2.dot, transition 'b' was rendered completely disconnected 
    with zero incoming and zero outgoing arrows:

        "a" -> p1;
        p1  -> "c";
        "c" -> p0;

        "b";  // <-- Floating alone in empty space! Completely disconnected!


5. WHY IS THIS PETRI NET MATHEMATICALLY INCORRECT?
--------------------------------------------------------------------------------
Leaving transition 'b' with no input places causes three major errors:
  1. Violation of Event Effectiveness:
     Classical Petri net synthesis axioms (Ehrenfeucht & Rozenberg 1990, 
     Cortadella et al. 1998) dictate that every event must have at least one 
     preregion guarding its execution.
  2. Language Explosion (Spurious Executions):
     In standard Petri net execution semantics, a transition without input 
     places is enabled at ANY marking and can fire an infinite number of times.
     The resulting net accepted illegal traces such as:
         b -> b -> b -> a -> c
     even though in reality 'b' can NEVER execute before 'a'!
  3. Loss of Causality:
     The causal connection where 'a' initializes the execution window for 'b', 
     and 'b' loops on its own token, was completely lost.


6. THE CORE INSIGHT & OUR SOLUTION
--------------------------------------------------------------------------------
The published assumption in Carmona et al. (2010) was:
    "Minimal regions are always sufficient to connect all events."

Our discovery proves this assumption is FALSE when an activity's execution 
lifetime spans across multiple sequential phases. In such cases, the ONLY region 
that can validly guard the event is a COMPOSITE (non-minimal) region.

Our Algorithmic Enhancement (Event-Effectiveness Constrained Relaxation):
Instead of unconditionally deleting all non-minimal regions, we introduced an 
Event Effectiveness check:

    Step 1: Compute the strictly minimal regions.
    Step 2: For every event 'e':
            Check: Does 'e' have at least one input place in the minimal set?
            If NO:
              - Do NOT leave 'e' orphaned!
              - Search the candidate pool already discovered during BFS.
              - Find the candidate region that covers ER(e) (in our case, r_3).
              - Retain r_3 as an authorized place!

The Result:
  - Region r_3 is retained as place p_2.
  - Place p_2 receives a token when 'a' fires (a -> p_2).
  - Event 'b' loops on place p_2 (p_2 -> b -> p_2).
  - Transition 'b' is fully connected, cannot fire before 'a', and the 
    synthesized Petri net is 100% correct, connected, and faithful to the traces.


7. SUMMARY IN ONE SENTENCE
--------------------------------------------------------------------------------
When an activity loops across sequential phases, its only valid precondition is 
a composite region; by unconditionally deleting non-minimal regions, the standard 
textbook algorithm accidentally deletes the ONLY place capable of connecting that 
activity, leaving it floating disconnected in the synthesized Petri net.
